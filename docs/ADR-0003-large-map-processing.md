# ADR-0003: надёжная обработка больших карт

- Статус: принято
- Дата: 2026-08-15

## Контекст

При конвертации растрового MBTiles размером около 930 МБ пользователь сообщил
об остановке на 33%. Размер сам по себе не является ограничением PMTiles, но
большие архивы выявили несколько проблем приложения:

- вывод дочерних PMTiles/GDAL процессов накапливался до завершения этапа;
- временные файлы всегда попадали в системный `%TEMP%`;
- для стороннего MBTiles без индекса запросы могли выполняться крайне медленно;
- дедупликация растров могла занимать больше времени, чем была полезна;
- при ошибке не оставалось полного диагностического журнала.

## Решение

1. Читать объединённый stdout/stderr дочернего процесса во время выполнения,
   распознавать строки PMTiles с `%` и прогресс GDAL вида `10...20...`.
2. Показывать название текущего этапа, его процент и общее прошедшее время.
   Для SQLite-операций без доступного процента использовать неопределённый
   индикатор, не оставляя на экране старое значение.
3. Разрешить пользователю выбрать временный каталог и передавать его PMTiles
   CLI через `--tmpdir`; все промежуточные каталоги Python создавать там же.
4. До запуска рассчитывать консервативный запас места для временного и
   итогового дисков. Небольшой дефицит требует подтверждения, критический
   блокирует запуск.
5. Проверять индекс `zoom_level, tile_column, tile_row`. Недостающий индекс
   создавать только в рабочей копии MBTiles. Исходный файл остаётся неизменным.
6. Добавить быстрый режим `--no-deduplication` для больших растров, принимая
   возможное увеличение итогового PMTiles.
7. Сохранять рядом с результатом текстовый `.diagnostic.log`, включая этапы,
   время, сообщения инструментов и ошибку.

## Последствия

- длительное индексирование больше не выглядит остановкой на старом проценте;
- пользователь может перенести нагрузку с переполненного системного диска;
- сторонние MBTiles без индекса обрабатываются предсказуемее;
- быстрый режим является явным компромиссом между временем и размером;
- журнал упрощает удалённую диагностику без передачи самой карты;
- консервативная оценка места для GeoTIFF/KMZ может предупреждать даже когда
  конкретной карте потребуется меньше места, поскольку степень распаковки
  заранее неизвестна.
