# ADR-0002: единый конвейер импорта растровых карт

- Статус: принято
- Дата: 2026-08-13

## Контекст

THS2 читает растровый PMTiles v3. Пользовательские карты приходят не только из
SAS.Planet: встречаются готовые MBTiles, геопривязанные GeoTIFF/KMZ и каталоги
тайлов XYZ. Поддержка каждого источника отдельным конвертером привела бы к
разным правилам метаданных и проверки результата.

## Решение

Каждый импортёр только читает исходник и создаёт временный растровый MBTiles:

```text
SAS CacheType=71 ─────────────────┐
MBTiles ──────────────────────────┤
GeoTIFF / KMZ ────────────────────┤
XYZ z/x/y ────────────────────────┼─> MBTiles ─> PMTiles CLI convert ─> verify ─> report.json
Global Mapper folder/ZIP Z/y/x ───┘
```

После нормализации используется один проверенный путь упаковки официальным
PMTiles CLI. Импорт GeoTIFF/KMZ выполняет GDAL: проверяет геопривязку,
перепроецирует в EPSG:3857, задаёт разрешение максимального масштаба и создаёт
обзорные уровни до минимального масштаба. XYZ импортируется стандартной
библиотекой Python с преобразованием строки XYZ в TMS.

Папка Global Mapper читается только для чтения, а ZIP — потоково без
предварительной распаковки. Раскладка
`Z/y/x` принимается только при наличии безопасного `*.gm_source_def.xml` с
официальным `creator` Global Mapper и явным шаблоном `Z%z/%y/%x.<ext>`. XML ограничен
256 КиБ, DOCTYPE/ENTITY запрещены; ZIP проходит проверки путей, типов файлов,
шифрования, объёма, коэффициента сжатия, размеров тайлов, координат и
дубликатов. Временный MBTiles помечается
`source_layout=global-mapper-z-y-x`.

GDAL остаётся необязательной внешней зависимостью. Компактная Windows-сборка
автоматически использует GDAL из OSGeo4W, QGIS, `PATH`, `GDAL_HOME` или
`bin/gdal`. Остальные форматы работают без GDAL.

## Последствия

- все итоговые файлы проходят одинаковую проверку PMTiles v3;
- исходники и кэш SAS.Planet никогда не изменяются;
- добавление нового формата сводится к новому импортёру в MBTiles;
- размер компактной сборки не увеличивается на сотни мегабайт библиотек и
  таблиц преобразования GDAL;
- для GeoTIFF/KMZ пользователю пока требуется установленный OSGeo4W или QGIS;
- изображения JPG/PNG без геопривязки и векторные форматы требуют отдельных
  пользовательских сценариев и в это решение не входят.

## Отклонённые варианты

- **Отдельная реализация PMTiles для каждого формата.** Дублирует упаковку,
  метаданные и проверку.
- **Включить весь OSGeo4W в обычную сборку.** Существенно увеличивает размер и
  усложняет обновление лицензий и данных координатных преобразований.
- **Считать обычное изображение геопривязанным.** Без координат или контрольных
  точек невозможно получить корректную карту.
