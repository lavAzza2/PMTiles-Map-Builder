# ADR-0001: THS2 Map Builder как внешнее приложение

- Статус: принято для MVP
- Дата: 2026-07-31

## Контекст

Пользователь готовит растровые офлайн-карты в обычной SAS.Planet и переносит
их в THS2 как PMTiles v3. Нужно сократить число технических действий, не
форкая SAS.Planet и не рискуя пользовательским кэшем.

Проверено на установленной SAS.Planet 260404 x64:

- `cache_sqlite\sat` имеет CacheType=71;
- каждый `.sqlitedb` содержит таблицу `t(x,y,v,c,s,h,d,b)` с первичным ключом
  `(x,y,v)`;
- `x/y` — глобальные координаты XYZ, `v=0` — обычная версия тайла, `b` —
  изображение;
- папка SAS `zN` соответствует стандартному zoom `N-1`;
- путь БД кодирует блоки: каталоги `floor(x/1024)\floor(y/1024)`, имя
  `floor(x/256).floor(y/256).sqlitedb`;
- `LastSelection.hlg` — текстовый многоугольник WGS84 и устойчивый способ
  получить последнее выделение без управления интерфейсом SAS.Planet;
- экспорт SAS.Planet создаёт обычный MBTiles со схемой TMS.

В исследованных материалах и установленной сборке не найден стабильный
публичный API для добавления команды в интерфейс SAS.Planet. Поэтому термин
«плагин» для MVP не используется.

## Решение

Создать отдельное Windows-приложение, работающее рядом с неизменённой
SAS.Planet.

Надёжный запасной процесс:

1. SAS.Planet скачивает выбранную область.
2. SAS.Planet экспортирует её в MBTiles.
3. THS2 Map Builder конвертирует MBTiles официальным PMTiles CLI.
4. Помощник запускает `pmtiles verify` и пишет JSON-отчёт рядом с картой.

Основной процесс для проверенной версии SAS.Planet 260404:

1. Помощник читает `LastSelection.hlg`.
2. По bbox и диапазону масштабов открывает только нужные CacheType=71 БД в
   SQLite `mode=ro`.
3. Собирает временный MBTiles, меняя XYZ `y` на TMS `y`.
4. Конвертирует и проверяет PMTiles тем же официальным CLI.

Прямой режим использует прямоугольную оболочку многоугольного
выделения. Это предсказуемо и не теряет пограничные тайлы, но для сложного
многоугольника может добавить тайлы за его контуром.

## Почему не форк и не «плагин»

Форк SAS.Planet создаст отдельный дистрибутив, обязанность регулярно сливать
изменения и повышенный риск затронуть скачивание и кэш. Для одной команды
экспорта это несоразмерно. Решение можно пересмотреть, если появится
документированный стабильный API расширений с поддерживаемой точкой для
экспорта текущего выделения.

## Сравнение MVP

| Критерий | Наблюдение за MBTiles | Прямая сборка из кэша |
|---|---|---|
| Совместимость | Высокая: публичный формат | Средняя: внутренняя схема SAS |
| Риск для кэша | Нет | Низкий при `mode=ro` |
| Полнота тайлов | SAS отвечает за экспорт | Нужно отдельно выявлять пропуски |
| Шаги пользователя | Есть экспорт MBTiles | Почти «одна кнопка» |
| Поддержка разных CacheType | Не нужна | Нужен адаптер на каждый тип |
| Выбор для MVP | Запасной путь | Основной после проверки на 4383 тайлах |

Автоматическое наблюдение за папкой MBTiles не выбрано для первого интерфейса:
без
надёжной привязки экспортированного файла к источнику, выделению и завершению
записи оно может конвертировать не тот или ещё открытый файл. Прямая сборка
даёт желаемый сценарий «скачал — создал карту» без такого фонового риска.
Безопасный следующий шаг для MBTiles — список новых файлов с явным
подтверждением пользователя.

## Безопасность, права и атрибуция

- Кэш SAS.Planet никогда не изменяется и открывается только на чтение.
- Результат и временные файлы создаются отдельно.
- Существующий PMTiles не перезаписывается без явного выбора пути в интерфейсе.
- Помощник не скачивает тайлы из интернет-источников.
- Пользователь обязан проверить право на офлайн-хранение/использование
  выбранного источника и указать требуемую атрибуцию.

## Критерии готовности MVP

- Конвертация валидного растрового MBTiles в PMTiles v3.
- Проверка архива официальным CLI.
- Прямое read-only чтение CacheType=71 по `LastSelection.hlg`.
- Диапазон zoom и число найденных/ожидаемых тайлов видны в отчёте.
- Понятный интерфейс без командной строки и JSON-отчёт рядом с результатом.
